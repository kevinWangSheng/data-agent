# 小范围自动改写 Skill：从开发集失败起草修改，初筛通过的开 PR 等人批

日期：2026-11-23。决策来自当天的讨论（预算由人定；其余按仓库规矩和上游多数做法定，人确认）。取证笔记：`docs/research/2026-11-23-skill-self-improvement.md`。

## Problem Statement

plan §3 定了"失败 → 改 Skill"：agent 写归因报告、给具体修改，人审后提交，不做全自动改写。现在 `evals/attribute.py` 只起草建议，不应用、不重测；从建议到"改了有没有用"全靠人手工拆工单、改 Skill、跑初筛（ADR-0008）。缺一个把"起草 → 应用成候选 → 初筛 → 交给人"串起来的闭环。

## Solution

一条手动运行的命令 `evals improve`：

1. 对一次开发集运行的失败跑 `attribute`，得到按失败模式分组的修改建议；
2. 挑最多 3 个失败模式，每个生成一个**增量**修改的候选 Skill 版本（各自一个分支、一个提交）；
3. 每个候选按 ADR-0008 初筛：目标题加回归集，判定用 `evals/accept.py`；
4. 通过的候选开 draft PR，附归因、diff 和初筛结果，由人决定合不合；没通过的只进报告。

## Implementation Decisions

### 输入与诊断

- 只用 data-eng-bench **开发集**的失败（ADR-0004）；不用留出集，不用 DAB（ADR-0005）。输入是一次已有的开发集运行（job 目录），不新跑基线。
- 诊断沿用 `attribute.py`：读轨迹、Skill、题面、验证器输出，**不给标准答案**；标签 FM1–FM4、逐字引用 Skill 原文、修改不点名题目和数据（现有校验不变）。

### 候选

- 一个候选只针对一个失败模式（ADR-0008 "一个失败模式一个改动"），写明目标题（该模式下失败的开发集题）。
- 增量修改：优先收窄或替换现有条目，不整段重写（ACE 的整段重写塌缩、SignalPilot "优先收窄"）。每个候选净增不超过 10 行；超过的建议不生成候选，只进报告。
- 生成方式：judge 模型给出"原文片段 → 新片段"的替换（或在某条后插入），我们的代码按逐字匹配应用；匹配不到就丢弃这个候选，不让模型直接写整个文件。
- 挑选：按失败模式覆盖的失败次数从多到少取前 3 个；同一份 Skill 的同一段只出一个候选。
- 每个候选是本地分支 `skill-improve/<日期>-<n>` 上的一个提交，基于输入运行的 commit，只改 `skills/`。

### 初筛与判定

- 每个候选：目标题 + 回归集（`evals/regression.json`，12 题），只跑 `full`，每题 3 次，在服务器上用 `evals board`（经 `da-remote`）。每个候选不超过 30 题，属于默认放行的小额运行（plan §10）。
- 判定用 `evals/accept.py`，规则即 ADR-0008：目标题成功合计严格高于旧版、回归集不退步（含补跑规则）、旧版结果按复用条件处理。门槛不改。
- 候选之间互相独立，各自对比同一个旧版；不组合候选。

### 交给人

- 通过的候选：推送分支并开 **draft PR**（`gh pr create --draft`），正文含失败模式、目标题、归因引用的 Skill 原文、diff、初筛结果与判定、花费，以及一句固定说明："开发集噪声大（单配置标准误约 ±2.2–2.5 分），通过初筛不等于显著提升"。不合并，不改 PR 状态；合不合由人决定，之后走现有的审查和合并流程（AGENTS.md 第 5–7 步）。推送和开 PR 由本 spec 授权，仅限 `skill-improve/` 分支。
- 没通过的候选：只写进本轮报告（`runs/improve-<日期>/report.md`），分支留在本地不推送。
- 报告：每个失败模式的归因、生成或丢弃的原因、每个候选的初筛结果和判定、总花费。

### 预算（人定）

- 每轮最多 3 个候选，总花费上限 $25（含归因）；超过就停止剩下的初筛，报告写明停在哪里。
- 初筛前查模型账户余额、跑预检（ADR-0008 的预检规则，`evals/readiness.py`）；连续基础设施报错就停（沿用现有快速失败）。

## Testing Decisions

单元测试不调模型、不连服务器、不推送：judge、`da-remote`、`gh` 都用替身。

- **输入范围**：输入里有留出题的 trial 时，留出题不进归因、不进候选的目标题；DAB 的运行被拒绝。
- **候选生成**：替换片段逐字匹配才应用；匹配不到、净增超过 10 行、改到 `skills/` 以外的文件，都不生成候选并在报告里写明原因；同一段只出一个候选；按失败次数取前 3 个。
- **分支与提交**：每个候选一个分支、一个提交、只改 `skills/`；`skill_version` 随之变化。
- **初筛**：每个候选跑的题是目标题加回归集、只跑 `full`、每题 3 次；题数不超过 30。
- **判定**：用 `accept.py` 的结果；通过的调用 `gh pr create --draft`，正文里有固定的噪声说明；没通过的不推送、不开 PR。
- **预算**：累计花费超过 $25 时停止后续初筛，报告写明停在哪里。

## 验收

- `make check` 通过。
- 真实跑一轮：输入用最近一次开发集运行（`b7c6071` 的 `full`），走完"归因 → 候选 → 服务器初筛 → 判定"，实际花费不超过 $25。至少生成 1 个候选并跑完初筛；有通过的就开出 draft PR，人看 PR 内容是否可读、修改是否通用。
- 一个都没通过也算验收通过，只要报告完整、花费在上限内；结论照实写进报告和 ADR-0008 的 Update。

## Out of Scope

- 全自动合并、无人审批的改写（plan §3）。
- 整段重写 Skill、新建 Skill。
- 组合多个候选、多轮迭代搜索（GEPA 式的进化）。
- 用留出集或 DAB 的失败。
- 定时自动运行。
- 改 ADR-0008 的判定门槛。
