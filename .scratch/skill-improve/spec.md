# 小范围自动改写 Skill：从开发集失败起草修改，初筛通过的开 PR 等人批

日期：2026-11-23。决策来自当天的讨论（预算由人定；其余按仓库规矩和上游多数做法定，人确认）。取证笔记：`docs/research/2026-11-23-skill-self-improvement.md`。

## Problem Statement

plan §3 定了"失败 → 改 Skill"：agent 写归因报告、给具体修改，人审后提交，不做全自动改写。现在 `evals/attribute.py` 只起草建议，不应用、不重测；从建议到"改了有没有用"全靠人手工拆工单、改 Skill、跑初筛（ADR-0008）。缺一个把"起草 → 应用成候选 → 初筛 → 交给人"串起来的闭环。

## Solution

一条手动运行的命令 `evals improve`：

1. 对一次开发集运行的失败跑 `attribute`，得到按失败模式分组的修改建议；
2. 挑最多 3 个失败模式，每个生成一个**增量**修改的候选 Skill 版本（各自一个分支、一个提交）；
3. 每个候选按 ADR-0008 初筛：目标题加回归集，判定用 `evals/accept.py`；
4. 通过的候选开 draft PR，附归因、diff 和初筛结果，由人决定合不合；没通过的只进报告。

## Implementation Decisions

### 输入与诊断

- 只用 data-eng-bench **开发集**的失败（ADR-0004）；不用留出集，不用 DAB（ADR-0005）。输入是一次已有的开发集运行（job 目录），不新跑基线。
- 诊断沿用 `attribute.py`：读轨迹、Skill、题面、验证器输出，**不给标准答案**；标签 FM1–FM4、逐字引用 Skill 原文、修改不点名题目和数据（现有校验不变）。
- （Update 2026-11-24，人定）输入与旧版：取代上面"输入是一次已有的开发集运行，不新跑基线"。
  - 126 合入后的第一轮，先在当时的 main 上新跑一次开发集：30 题 × 3，`full`。人已批准这次运行，它不计入每轮 $25 上限；b7c6071 同样范围的运行花了 $8.83。
  - 这次运行既是归因的输入，也是 `accept.py` 的旧版。
  - 之后的轮次在它满足 `accept.py` 复用条件时复用它（14 天、benchmark commit 相同等，`evals/accept.py:242-291`）。不再满足时，这一轮在报告里写明需要新跑一次开发集，自己不开跑。候选照常初筛，判定是 `rerun-old`（未判定），和工单 125 已合入的验收测试一致（Update 2026-11-24，主会话对照测试补明）。
  - 原因：b7c6071 的 Skill 版本 `e075718e1fd7` 不在当前 `skill_sets()` 里（`evals/attribute.py:145`），按 `:436-441` 一题也归因不了；它也超过了 `MAX_AGE` 14 天（`evals/accept.py:51`）。
- （Update 2026-11-24，主会话对照代码更正）输入可以是多个 job 目录，按配置合并，和 `load_jobs` 一样（`evals/report.py:218`）。一次开发集运行可能分在几个 OUT 里，例如 b7c6071 的 `full` 分在 `runs/u1-target`、`u1-full-rest`、`u2-rest`。而 `attribute` 只收一个 job（`evals/attribute.py:501`、`:518`）。
- （Update 2026-11-24，主会话对照代码更正）分组：`attribute` 的输出是一个失败一条（`evals/attribute.py:540`），没有分组、没有"段"这个单位，也不给替换。
  - "失败模式"的分组键是 FM 标签加上归因逐字引用的 Skill 段落（`skill` + `skill_quote`）。
  - 按组里的失败次数取前 3 个。
  - 替换由第二次 judge 调用生成，用新的回复格式。格式由 126 定，入口的空壳签名由 125 定。

### 候选

- 一个候选只针对一个失败模式（ADR-0008 "一个失败模式一个改动"），写明目标题（该模式下失败的开发集题）。
- 增量修改：优先收窄或替换现有条目，不整段重写（ACE 的整段重写塌缩、SignalPilot "优先收窄"）。每个候选净增不超过 10 行；超过的建议不生成候选，只进报告。
- 生成方式：judge 模型给出"原文片段 → 新片段"的替换（或在某条后插入），我们的代码按逐字匹配应用；匹配不到就丢弃这个候选，不让模型直接写整个文件。
- 挑选：按失败模式覆盖的失败次数从多到少取前 3 个；同一份 Skill 的同一段只出一个候选。
- 每个候选是本地分支 `skill-improve/<日期>-<n>` 上的一个提交，基于输入运行的 commit，只改 `skills/`。
  - （Update 2026-11-24，人定）这个 commit 就是上面新跑的开发集所在的 main，所以 `skill_sets()` 认得它的 Skill 版本。
- （Update 2026-11-24，主会话对照代码更正）下面这些细节由 125 写进契约，合并时人审：
  - 净增行数 = 加的行数减删的行数，正好 10 行算通过；
  - 目标题和回归集取并集，超过 30 题就丢弃这个候选，写进报告。

### 初筛与判定

- 每个候选：目标题 + 回归集（`evals/regression.json`，12 题），只跑 `full`，每题 3 次，在服务器上用 `evals board`（经 `da-remote`）。每个候选不超过 30 题，属于默认放行的小额运行（plan §10）。
- 判定用 `evals/accept.py`，规则即 ADR-0008：目标题成功合计严格高于旧版、回归集不退步（含补跑规则）、旧版结果按复用条件处理。门槛不改。
- 候选之间互相独立，各自对比同一个旧版；不组合候选。
- （Update 2026-11-24，主会话对照代码更正）初筛命令：取代上面的 `evals board`。
  - 初筛跑 `ablate --split dev --config full --trials 3 --task …`（`evals/ablate.py:161-200`，`--task` 的处理在 `:851-859`），仍经 `da-remote start`。
  - 不用 `board`：它用登记处 v1.0，回归题 `dbt-cart-abandonment-recovery`（`board.ZERO_TASK`，`evals/board.py:78`）在那里每次都得 0，所以每个候选都会判退步。在 tasks checkout 上这题是 3/3（`runs/dev-paired/summary.md:12`）。
  - 用 `ablate`，benchmark commit 也和开发集那次运行一致（`evals/ablate.py:588`；`board` 记的是 `DATASET_VERSION`，`evals/board.py:256`），可以复用旧版。
- （Update 2026-11-24，主会话对照代码更正）判定：`accept.py` 现在要求新 job 覆盖整个开发集（`evals/accept.py:134`、`evals/report.py:348-363`），还会检查整个开发集的点估计（`evals/accept.py:149-154`）。初筛只跑目标题加回归集，所以 126 给 `accept.py` 加一个初筛模式，只查下面三项：
  - 目标题成功次数严格高于旧版；
  - 回归集不退步，含补跑规则；
  - 复用条件。

  这就是上面一条写的规则，门槛不变。
- （Update 2026-11-24，主会话对照代码更正）判定之后由 125 写进契约，合并时人审：
  - `rerun-regression`：在预算内自动补跑一次，补跑的题算进 30 题上限；
  - `rerun-old`：报告里记为"未判定"。

### 交给人

- 通过的候选：推送分支并开 **draft PR**（`gh pr create --draft`），正文含失败模式、目标题、归因引用的 Skill 原文、diff、初筛结果与判定、花费，以及一句固定说明："开发集噪声大（单配置标准误约 ±2.2–2.5 分），通过初筛不等于显著提升"。不合并，不改 PR 状态；合不合由人决定，之后走现有的审查和合并流程（AGENTS.md 第 5–7 步）。推送和开 PR 由本 spec 授权，仅限 `skill-improve/` 分支。
- 没通过的候选：只写进本轮报告（`runs/improve-<日期>/report.md`），分支留在本地不推送。
- 报告：每个失败模式的归因、生成或丢弃的原因、每个候选的初筛结果和判定、总花费。
- （Update 2026-11-24，人定）推送：取代上面的"分支留在本地不推送"。
  - 每个候选的 `skill-improve/*` 分支在初筛**之前**推送，因为 `da-remote setup` 只从 origin fetch（`scripts/da-remote:306-341`）。
  - 初筛后，没通过的候选删掉远端分支，只写进报告；通过的照旧开 draft PR。
  - 推送和删除都只限 `skill-improve/` 分支。
  - 每次推送都会触发 CI（`.github/workflows/check.yml:3-5`）。

### 预算（人定）

- 每轮最多 3 个候选，总花费上限 $25（含归因）；超过就停止剩下的初筛，报告写明停在哪里。
- 初筛前查模型账户余额、跑预检（ADR-0008 的预检规则，`evals/readiness.py`）；连续基础设施报错就停（沿用现有快速失败）。
- （Update 2026-11-24，主会话对照代码更正）花费的口径由 125 写进契约，合并时人审：
  - 花费 = `evals spend` 算的实付花费（`evals/spend.py`，闲时半价 `:35`）加上 judge 的花费；
  - 每次初筛开始前检查一次；
  - 每次初筛给 `ablate` 的 `--budget`（必填，`evals/ablate.py:164`）等于剩下的额度。
  - `ablate` 的预检每次还会多跑 1 个冒烟 trial（`evals/ablate.py:893`），这部分也算进花费。
- （Update 2026-11-24，主会话对照代码更正）DAB 的输入被拒绝。PR 正文的那句固定说明一字不改。配置仍是 `full`。

## Testing Decisions

单元测试不调模型、不连服务器、不推送：judge、`da-remote`、`gh` 都用替身。

- **输入范围**：输入里有留出题的 trial 时，留出题不进归因、不进候选的目标题；DAB 的运行被拒绝。
- **候选生成**：替换片段逐字匹配才应用；匹配不到、净增超过 10 行、改到 `skills/` 以外的文件，都不生成候选并在报告里写明原因；同一段只出一个候选；按失败次数取前 3 个。
- **分支与提交**：每个候选一个分支、一个提交、只改 `skills/`；`skill_version` 随之变化。（Update 2026-11-24，人定）分支在初筛前推送，没通过的远端分支在初筛后删除。
- **初筛**：每个候选跑的题是目标题加回归集、只跑 `full`、每题 3 次；题数不超过 30。
- **判定**：用 `accept.py` 的结果；通过的调用 `gh pr create --draft`，正文里有固定的噪声说明；没通过的不推送、不开 PR。
- **预算**：累计花费超过 $25 时停止后续初筛，报告写明停在哪里。

## 验收

- `make check` 通过。
- 真实跑一轮：（Update 2026-11-24 第二次，人定）推到里程碑：所有改 agent 行为的工单合入后跑开发集统一评估（plan 的"全量只在里程碑"），improve 第 1 轮用那次的 `full` 结果当输入和旧版，不为它单独跑开发集；126 合入时只验收代码和测试。（Update 2026-11-24 第一次，人定，已被上一句取代）输入改为 126 合入后在 main 上新跑的开发集 `full`（30 题 × 3，已批准，不计入 $25）；原写的是"最近一次开发集运行（`b7c6071` 的 `full`）"。走完"归因 → 候选 → 服务器初筛 → 判定"，实际花费不超过 $25。至少生成 1 个候选并跑完初筛；有通过的就开出 draft PR，人看 PR 内容是否可读、修改是否通用。
- 一个都没通过也算验收通过，只要报告完整、花费在上限内；结论照实写进报告和 ADR-0008 的 Update。

## Out of Scope

- 全自动合并、无人审批的改写（plan §3）。
- 整段重写 Skill、新建 Skill。
- 组合多个候选、多轮迭代搜索（GEPA 式的进化）。
- 用留出集或 DAB 的失败。
- 定时自动运行。
- 改 ADR-0008 的判定门槛。
