# 网页界面：运行页、历史列表、评测页，加一个只读的在线版

日期：2026-11-15。Status: ready-for-agent。

决策来源：`docs/plan.md` §2"网页界面的基础决定"（Q1–Q29）和"样板"（选定 B、Q30–Q41）、§5"界面"。上游取证：`docs/research/2026-11-01-upstream-web-ui.md`。样板（只在本机，不进 git）：`runs/web-prototypes/b/`，共用数据在 `runs/web-prototypes/data/runs/`。

## Problem Statement

项目现在只有命令行和一份事件文件。两类人因此看不到 agent 是怎么工作的：

- **面试官或同行**从 README 点进来，不会安装任何东西，只停留几分钟。他们现在只能读文字和分数，看不到 agent 加载 Skill、按引用取上下文、写 SQL、被验证者判 FAIL 后修好的过程，也没法逐题核对评测分数。
- **自己部署的人**要在终端里拼一条很长的 `data-agent run` 命令，运行过程只能读 JSONL 文件，没有历史列表，也不方便取消运行或查看花费。

## Solution

做一个网页界面，分两种形态，共用同一套前端：

- **本地版**：`data-agent web` 一条命令启动，只监听本机地址。在页面上填任务、选类型、数据源和配置后提交，实时看过程，拿到答案和结果表；可以取消运行、看花费、翻历史。
- **在线版**：纯静态站点，发布在 `https://kevinwangsheng.github.io/data-agent/`。只读，访客不能真跑。第一屏是一条自动回放的真实运行，带两个榜单分数；另有 3 条精选运行、开发集 270 个 trial 的回放、评测页。

三个页面：

- **运行页**（提交和回放是同一页）：三栏布局，照样板 B。
  - 左栏：大纲（阶段、每次验证）和缩略时间轴，带跳转到验证、报错和拒绝、SQL 的筛选。
  - 中栏：选中步骤或某次验证的详情；没选中时显示关键时刻列表。
  - 右栏：答案、结果表、验证结论、花费和用时。
- **历史列表**：所有运行，一行一条。
- **评测页**：两个榜单的总分、消融对比、开发集逐 trial 表格。

## User Stories

面试官（在线版）：

1. 作为面试官，我想打开链接后第一屏就是一条真实运行在自动回放，这样不用点任何东西就能看到 agent 在做什么。
2. 作为面试官，我想在第一屏看到两个榜单的分数和误差，这样一眼知道这个项目的水平。
3. 作为面试官，我想在几条精选运行之间切换，这样能分别看查数、dbt 成功、dbt 失败三种情况。
4. 作为面试官，我想看到任务原文、类型、配置、模型、结果、用时、轮数、花费，这样知道这条运行是什么条件下跑的。
5. 作为面试官，我想不滚动就看到最终答案和它的结果表，这样先知道结论再看过程。
6. 作为面试官，我想看到答案依据的是哪条查询并能跳过去，这样能核对答案不是编的。
7. 作为面试官，我想让 270 次工具调用的长运行在一两屏内分成几个阶段，这样能看出这条运行的经过。
8. 作为面试官，我想一键只看验证、只看报错和拒绝、只看 SQL，这样不用翻完整日志。
9. 作为面试官，我想看到每次验证的逐模型、逐项结论表格，每项带名字，这样知道验证者查了什么。
10. 作为面试官，我想展开验证者的完整报告和它自己的工具调用，这样能看到结论的依据。
11. 作为面试官，我想在一次 FAIL 之后看到主 agent 改了什么、下一次验证的结果，这样能看到闭环确实起作用。
12. 作为面试官，我想看到每条 SQL 带语法高亮、结果是真正的表格，这样读起来不费劲。
13. 作为面试官，我想让被守卫或只读网关拒绝的调用有明显标记并注明是哪一种拒绝，这样知道安全机制在哪里生效。
14. 作为面试官，我想看到 agent 加载了哪个 Skill、用了哪些上下文工具，这样理解"先引用后展开"是怎么回事。
15. 作为面试官，我想让思考默认收起、需要时展开，这样页面不被长文本淹没。
16. 作为面试官，我想在失败的运行旁边看到评分结果和失败原因，这样知道项目没有只挑好的展示。
17. 作为面试官，我想控制回放：播放、暂停、倍速、跳过空闲、直接显示全部，这样 50 分钟的运行能在一分钟内看完。
18. 作为面试官，我想让页面跟随系统的深色或浅色并能手动切换。
19. 作为面试官，我想把某条运行的链接发给别人，对方打开就是那条运行的完整视图。
20. 作为面试官，我想在评测页看到各配置通过率的条形图和误差线，这样知道每一层带来多少、哪些差别不显著。
21. 作为面试官，我想在开发集的表格里按配置和成败筛选，并点进任意一个 trial 看回放。
22. 作为面试官，我想看到留出集和全量只有汇总数字并说明原因，这样知道留出集没有被偷看。
23. 作为面试官，我想看到 DAB 各数据集的小结和轨迹的下载链接。
24. 作为面试官，我想看到"新建运行"是不可用的并说明本地怎么启动，这样知道这是演示而不是坏了。
25. 作为用手机打开链接的人，我想第一屏的摘要和评测汇总能读。

自己部署的人（本地版）：

26. 作为部署的人，我想用一条命令启动界面，不需要另装 Node。
27. 作为部署的人，我想在表单里填任务、选类型、数据源和配置后提交。
28. 作为部署的人，我想只按名字选数据源，连接串和密钥不出现在浏览器里。

32. 作为部署的人，我想在历史列表里看到每条运行的任务、类型、配置、状态、用时、花费、开始时间，并点进去回放。

34. 作为部署的人，我想在提交失败时（数据源不存在、已有运行在跑）看到明确的原因。
35. 作为部署的人，我想让界面只监听本机地址，这样不会无意中把它暴露出去。

维护者：

36. 作为维护者，我想用一条命令把选定的运行导出成在线版的数据，导出时强制脱敏。
37. 作为维护者，我想让导出命令拒绝留出集的运行，这样不会误把留出集的逐题细节发出去。
38. 作为维护者，我想让 main 更新后在线版自动重新构建发布。
39. 作为维护者，我想让旧的事件文件（没有新字段）仍然能回放，只是少显示几样东西。

## Implementation Decisions

### 总体

- **前端**：Vite + React 19 + TypeScript 单页应用，客户端路由，Tailwind 4，recharts（只用于评测页），vitest，pnpm。放在 `web/`。
- **后端**：FastAPI + uvicorn，由 `data-agent web` 启动，只监听本机地址。它同时提供接口和构建好的前端文件。构建好的前端随 Python 包发布，使用的人不需要 Node。
- **一套前端，两个数据来源**：前端通过一个数据来源接口读数据，有两个实现：
  - 本地版：调后端接口。
  - 在线版：读静态 JSON 和 JSONL 文件。构建时用一个开关选定，在线版把提交和取消显示成不可用。
- **不用**：Next.js、`@assistant-ui/react`、SQLite、任何规定外观的组件库、聊天界面库。
- **时间线自己写**，不复制 SignalPilot 的 `chat-run-steps`、`run-timeline`、`tool-cards`。可以复制的小文件（SQL 高亮、SQL 排版、Markdown、回放控件）复制时保留版权头并登记到 `NOTICE`；不复制它的配色。

### 事件：新增和补充的字段

都是只加不改，旧事件文件保持可读。

- **新增 `task` 事件**，在 `version` 之后写一次：任务原文、任务类型、数据源名字。不含连接串。
- **`verifier_end.checks`**：每项检查除了结论，还带检查的名字。
- **最终答案**：标记哪一段文本是最终答案，并带上它依据的那条查询的 `tool_use_id`（没有就留空）。
- **被拒绝的调用**：`tool_end` 带一个拒绝种类字段，取值区分守卫和只读网关；没被拒绝时不带。
- **`verifier_dispatch`**：带上对应的 Agent 工具调用的 `tool_use_id`。
- **`version.skills`**（2026-11-15 人定，工单 83）：运行开始时注入主 agent 系统提示的 Skill 名字列表，按注入顺序。不是从工具调用推出的，也不是模型实际用到的。Skill 层关掉时为 `[]`；验证者的提示不算 Skill；只写名字，不写内容、路径或密钥。旧事件文件没有这个字段，视为未记录。
- **不补**：`sql` 事件的 `parent`（经 `tool_use_id` 找到工具调用再取）、验证者自己的思考和文本、失败的 `dbt run` 的 `is_error`。

字段名（2026-11-15 定，工单 73 的测试和工单 74 的实现都用这一组）：

| 内容 | 写法 |
|---|---|
| 任务 | 新事件 `task`：`task`（原文）、`task_type`（`query` 或 `dbt`）、`data_source`（名字） |
| 检查的名字 | `verifier_end.check_names`：检查编号 → 名字。`checks` 的结构不变 |
| 最终答案 | 新事件 `answer`：`text`、`sql_tool_use_id`（没有时为 null） |
| 拒绝种类 | `tool_end.rejected_by`：`guard` 或 `gateway`；没被拒绝时不带 |
| 验证派出的关联 | `verifier_dispatch.tool_use_id` |
| 注入的 Skill | `version.skills`：名字列表；Skill 层关掉时 `[]`（工单 83） |

### 运行视图模型（前端的核心模块）

一个纯函数，把一条运行的事件列表（可以是不完整的前缀）和可选的运行说明转成页面要显示的结构。实时显示和回放都只调它：回放是把按时间截断的前缀喂给它。

它产出：

- **运行概况**：任务、类型、配置、模型、数据源、状态、用时、轮数、花费、token。花费只用 `cost_usd`，不用 `sdk_cost_usd`。
- **步骤**：`tool_start`、`tool_end`、`tool_timing`、`sql` 按 `tool_use_id` 配成一步；每步有工具名、输入、结果、耗时、是否报错、是否被拒绝及种类、是否属于验证者。查询结果的文本表格解析成行和列，解析不了就保留原文。
- **验证派出**：每次派出一条，含序号、涉及的模型、逐模型逐项的结论和名字、总结论、完整报告、验证者自己的步骤。
- **阶段**：
  - 第一次验证之前，按步骤的工具种类分成：了解环境、探索数据、写并运行 dbt、自查。
  - 之后以每次验证为界：验证、修复、验证……
  - 查数运行没有验证，分成：了解环境、探索数据、回答。
- **关键时刻**：每次验证的结论、被拒绝的调用、报错、最终答案，各一条，指向对应的步骤。
- **最终答案**：文本、依据的查询、那条查询的结果表。
- **注入的 Skill**（读 `version.skills`）**和上下文工具的使用次数**（`discover`、`hydrate`、`dictionary_search`）。
- **思考和叙述**（2026-11-16 人定，工单 86）：主 agent 的每条 `thinking` 和 `text` 各一条，含 seq、时间、文本，页面放在步骤之间、思考默认收起。验证者自己的思考和文本事件里没有记录（见上"不补"），不出现。
- **时间**（2026-11-16 人定，工单 86）：都是相对运行第一条事件 `ts` 的毫秒数；每步有开始时间，每次验证派出有开始和结束时间（还没结束为 `null`），供左栏缩略时间轴用。另有一个纯函数给出每条事件的时间，回放按它截前缀、跳过空闲间隔；页面不自己读事件字段。`ts` 缺失或解析不了时为 `null`，时间轴按序号排。

状态的取值：运行中、成功、失败、已取消。来源：

- 评测运行（运行说明里有评分结果）：成败读评分结果。
- 本地运行：读 `result` 事件；被取消的读后端给的状态。
- 没有 `result` 事件且没有其他信息：运行中。

旧事件文件缺新字段时的退路，和样板 B 现在的做法一致：

- 没有 `task` 事件：任务等信息读运行说明；都没有就显示"未记录"。
- 检查没有名字：显示编号。
- 没有最终答案标记：取最后一段文本；依据的查询取它之前最后一条成功的查询。
- 没有 `rejected_by`（新旧文件都适用，2026-11-15 定）：按结果里的文字和工具分辨——结果含 `Query blocked by the read-only gateway:` 记 `gateway`；`PreToolUse:<tool> hook error` 落在守卫注册的工具上（Bash、Read、Glob、Grep、Write、Edit，`agent.py:994-1005`）记 `guard`；落在其他工具上（验证者自己的 `deny_dispatch` 在 Agent、`deny_query` 在 MCP 查询工具）记 `unknown`，只标"被拒绝"；其他都不算被拒绝。按工具不按守卫的提示文字分，因为那段文字改过多次（工单 41、53）。验证者的 hook 是流程规则，不是安全机制，事件里不另记种类。
- 旧文件没有 `answer` 事件时，"最后一段文本"只在有 `result` 事件之后才算最终答案，免得运行中把最新的叙述当成答案。
- 旧文件的 `verifier_dispatch` 配给最近一次还没配上的 Agent 调用（事件顺序是 Agent 开始 → `verifier_dispatch` → `verifier_start`）。
- 没记录任务类型时：没有 Write、Edit 调用也没有验证的运行算查数运行。
- 查数运行的"回答"阶段从答案依据的那条查询开始。
- `verifier_dispatch` 没有关联：按它在 `verifier_start` 和 `verifier_end` 之间的位置对应。
- `version` 没有 `skills`：显示"未记录"，不从工具调用或 `layers.skill` 推断；和 `skills: []`（Skill 层关掉）区分开。

### 运行页

三栏，照样板 B；下面是和样板不同的地方：

- **没选中步骤时**，中栏显示关键时刻列表，不再重复阶段列表。
- **阶段**按上面的规则细分。
- **回放**：从链接打开的运行默认显示全部；控件有播放、暂停、倍速、跳过空闲间隔、显示全部。在线版第一屏自动回放那条短的查数运行，跳过空闲间隔，约 20–30 秒播完后停在全部显示。
- **长运行**：步骤列表按需渲染，1.2 MB 的运行展开到默认状态时页面不卡。
- **本地版**多一个提交表单（任务、类型、数据源、配置）和取消按钮；运行中时过程实时追加。
- 只做英文。深色、浅色都支持，默认跟随系统，可手动切换；颜色从一开始就用 CSS 变量。按 1280 宽以上设计；手机上只保证第一屏摘要能读。状态用颜色加文字表示，不用 emoji 当图标。

### 历史列表

一行一条运行：任务（截断）、类型、配置、状态、用时、花费、开始时间；按开始时间倒序；点一行进运行页。在线版的这一页列出精选运行，开发集的 trial 从评测页进。

### 评测页

- 两个榜单的总分：data-eng-bench 的通过率、误差、题数和次数；DAB 的 Pass@1、题数和次数。
- 消融对比：各配置通过率的条形图，带误差线；差别不显著的照实标出。
- 开发集 270 个 trial 的表格：题目、配置、第几次、成败、花费、用时；可按配置和成败筛选；每行链接到回放。
- 留出集和全量只显示汇总数字，并写一句原因（ADR-0004）。
- DAB 只显示各数据集的小结和两个配置的对比，轨迹链接到 release，不进站点。
- 失败归因只显示已有的，不为界面补做。

### 后端接口

四类，都在本机：

- **列出运行**：扫描运行目录，每条运行返回概况（从事件文件的头部和 `result` 事件取）。
- **读事件**：按序号游标返回某条运行的事件；同一个地址支持实时推送（SSE）：先补发游标之后的，再持续推送，运行结束后把剩余的推完就关闭；空闲时发 keepalive。每帧带事件序号，断线后用它续读。
- **提交运行**：收任务、类型、数据源名字、配置；校验后启动一个 `data-agent run` 子进程，返回运行的 id。
- **取消运行**：只对本服务启动的、还在跑的子进程有效，按它记录的那个进程号发终止信号。

另有一个只读接口返回可选的数据源名字、类型和配置列表，供表单用。

- **运行目录**：每条运行一个子目录，里面是事件文件。运行的 id 是目录名（开始时间加短随机串）。
- **运行索引**：这一版不建库，每次扫描目录。
- **密钥**：数据源的连接串只在后端的环境里，接口的输入和输出都不含它；事件文件照旧由 `EventLog` 脱敏。

### 导出命令和在线版数据

- 一条导出命令把选定的运行转成在线版的静态数据：每条运行一份事件文件和一份运行说明（标题、任务、类型、数据源名字、评分结果、失败原因、是否精选），加一份索引和评测页用的汇总。
- 目录结构（2026-11-15 定，工单 73 的测试已固定）：`index.json` = `{"runs": [运行说明, ...]}`，每条运行 `runs/<id>/events.jsonl` 和 `runs/<id>/meta.json`（与索引里那条相同）；评测页汇总文件的位置由工单 80 在此基础上增加。
- **强制脱敏**：导出时对每份文件跑一遍 `evals scrub` 的规则，不能关。
- **拒绝留出集**：对照评测清单，任何属于留出集的 trial 都拒绝导出并报错退出；留出集和全量只导出汇总数字。
- **精选运行也过留出集检查**（2026-11-15 人定，工单 84 改验收契约）：精选运行的 `notes.json` 必须有 `task_id`（来自榜单题目的运行）或 `local_data: true`（真正的本地数据运行）之一；两个都没有就拒绝，不当成本地运行。有 `task_id` 的和 trial 走同一套检查：只放行清单里开发集的题，留出集和清单里没有的题都拒绝。拒绝时只报数量，不打印题目 id、失败原因或结果。这两个字段只是导出的输入，输出的运行说明字段不变。
- 精选运行 3 条：README 快速上手的查数运行、一条 FAIL → 修 → PASS 的 full dbt 运行、一条评分失败的 dbt 运行。事件字段补完后各重跑或重选一次。
- 开发集统一评估的 270 个 trial 全部导出。

### 本地运行的数据源、工作目录和并发（Q38–Q40，人已确认）

- **数据源配置**：`data-agent web` 只在命令行明确给了配置文件参数时才读它（TOML），没有默认路径，不自动读 `~/.config/data-agent/`。每个数据源有名字、种类（DuckDB 文件路径，或存着 Postgres 连接串的环境变量名）、可选的 dbt 项目目录。连接串不进这个文件、HTTP 响应、子进程参数或事件，也不进浏览器；表单只显示名字。
  - 不给配置文件（2026-11-15 人定）：`/api/options` 的数据源列表为空，列出运行、读事件、SSE 照常可用；提交运行返回明确的 4xx，不启动任何进程。
  - 启动时校验配置：种类合法；DuckDB 要有文件路径，Postgres 要有环境变量名；dbt 项目目录给了就要存在。
- **工作目录**：每次运行有自己的目录。dbt 运行先把数据源的 dbt 项目目录复制进去再跑，原目录不动；DuckDB 数据源连库文件一起复制，Postgres 数据源直接写配置的那个库。查数运行用空的工作目录。
- **同时只跑一条**：已有运行在跑时，再提交会被拒绝并说明原因。这一版不处理并发。

## Testing Decisions

好的测试只测外部行为：给输入、看输出，不看内部怎么实现。三处测试接缝（Q34，人已确认）：

1. **运行视图模型**（vitest）：输入是真实的事件文件，断言产出的结构。
   - 夹具：三条样板用过的真实运行各取一份（查数 12 次调用；dbt 122 次调用、2 次验证 FAIL → PASS；dbt 270 次调用、10 次验证、评分失败），放进测试夹具目录，先过脱敏。大的那份如果超过大文件拦截的限制，就截成保留全部验证派出的前缀或压缩存放。
   - 要断言的行为：步骤配对的数量和工具名；验证派出的次数、每次的总结论和逐项结论；阶段的顺序和边界；关键时刻的清单；最终答案和依据的查询；被拒绝的调用及种类；验证者的步骤归属；状态的四种取值各自的来源；花费取 `cost_usd`；只给事件前缀时的结果（回放和实时显示）；旧文件缺新字段时的每一条退路。
   - 组件本身不写验收测试。
2. **后端接口**（pytest，FastAPI 测试客户端）：`data-agent run` 子进程换成一个假的，它按脚本往事件文件里写事件。
   - 要断言的行为：列出运行；按游标读事件；SSE 先补发再推送、结束后关闭、带序号续读不丢不重；提交后出现新运行；数据源名字不存在时拒绝；已有运行在跑时拒绝；取消只终止本服务启动的那个进程；接口的输出里没有连接串；只监听本机地址。
   - 先例：`tests/test_run_cli.py`、`tests/fake_model.py`、`tests/lifecycle_events.py`。
3. **导出命令**（pytest，命令行这一层）：
   - 要断言的行为：输出里的密钥、地址、主机名被脱敏；脱敏不能关；清单里属于留出集的 trial 被拒绝并以非零退出；输出的索引和运行说明字段齐全。
   - 先例：`tests/test_eval_scrub.py`、`tests/test_eval_report.py`。

新增事件字段的测试写在现有的事件测试里（先例：`tests/test_events.py`、`tests/lifecycle_events.py`），属于各自的实现工单，不算验收测试。

第一张工单写这三处的验收测试，标 `xfail`，人审过合并后才开始实现工单。
