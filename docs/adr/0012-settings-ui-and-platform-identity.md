# 设置界面、数据库和平台身份

日期：2026-11-27。人在对齐会话里逐条确认（`.scratch/product-config/decisions.md`"设置界面 + Slack 权限"一节，S1–S9）。依据：`docs/research/2026-11-27-chatbot-agent-config.md`（Slack 类产品、Claude in Slack、上游 SignalPilot/nao/dash 的配置）、`docs/research/2026-11-23-im-gateway-designs.md`（Hermes、OpenClaw、LangBot 的权限与配置）。取代 ADR-0011 第 5 条"登录、多用户、管理界面加数据库仍不做"，以及 ADR-0011 第 1 条里"配置文件是唯一来源"的含义；ADR-0011 其余决定不变。

## 背景

ADR-0011 定的配置只能由部署的人改服务器上的文件。人认为这样"都是死的配置"：团队在 Slack 里用 bot，使用的人应该能自己调整。同类产品（Claude in Slack、Onyx、Dust、Cursor、nao、SignalPilot）都是"部署参数在环境变量和文件里，行为设置在产品自己的设置界面里，身份和权限接平台"。

## 决定

1. **两类配置**：部署层（密钥、`[server]`、IM token、沙箱、数据源连接、可选模型列表、`[policy]`）只认文件和环境变量，设置页可看不可改；设置类（模型、数据源选用、MCP、Skill 与插件、说明、联网、effort、上限、是否要 @）存数据库，在设置页和 IM 里改。首次启动用 `config.toml` 播种，之后以数据库为准；每个值标来源，文件与数据库不一致时提示并允许管理员用文件覆盖（S7）。
2. **四层作用域**：组织 → 工作区 → 频道 → 个人。频道里 = 工作区 + 频道；一对一私聊 = 工作区 + 个人；`[policy]` 对所有层生效（S2）。数据结构从一开始就按多工作区（S5）。
3. **权限按设置的风险分**：访问和花费类只有工作区管理员（Slack Owner/Admin）改；行为类频道成员可改，`[policy]` 可收紧；频道改动在频道公告（S1）。组织层由配置文件列出的组织管理员改（S5）。
4. **临时覆盖**：频道或线程里任何人可在消息里覆盖模型、effort（`[policy]` 范围内，对线程生效）和从本频道已开放的数据源、MCP 里挑；Skill 和说明在线程开始时固定（S4）。
5. **身份**：网页用 Sign in with Slack；没接 Slack 的部署，组织管理员用部署层的管理令牌。Slack 角色和频道成员每次请求向 Slack 查、缓存 5 分钟（S9）。Telegram、Discord 套进同一结构，组织管理员由配置文件列出（S6）。
6. **会话**：一个线程一次会话；回复带"在网页打开"链接；频道会话该频道成员可看、私聊本人可看、组织管理员都能看；网页只看不接着聊（S8）。
7. **存储**：sqlite 单文件、带迁移；改动记录谁、何时、哪层、哪个键、改前改后（密钥类只记"改过"）（S9）。
8. **评测不变**：评测入口不碰数据库，只读 `evals/profiles/`（ADR-0011 第 3 条）。
9. **不分期**：排在后面的事记进 `decisions.md` 的"后续"清单（界面里新增数据源与工作区及其加密存储、个人连接器、Discord/Telegram 自己的登录与平台角色、配对码、Postgres），之后按依赖排进工单。

## Consequences

- 新 spec `.scratch/settings/spec.md`，工单 157–162；product-config 的 144、cloud-deploy 的 153、155 调整，156 作废（由 159、160 取代）。
- 网页从"本机单用户、无登录"变成 cloud 下有登录和按身份的权限；local 模式（只监听本机）仍不登录，本机用户即组织管理员。
- `docs/plan.md` §1 的"不做登录、多用户、权限"改为本 ADR。
